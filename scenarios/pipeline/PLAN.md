# 管线场景 —— 计划与决策

> 业务依据：`research/pipeline-business-fit.md`；数据源合规：`research/pipeline-sources.md`。
> 日常运行与口径细节见 `SKILL.md`；本文只留**为什么这么定**。

## 0. 要解决什么

nitrosamine 是「API 种子 → 按药名搜试验」（亚硝胺是监管硬触发）；本场景是「公司/资产 → 事件」，
目标是**在包装方案锁死之前（III 期/关键临床批）把目标企业捞出来**。

一句话：**按「剂型 × 期次 × 决策权」排序的公司×资产清单，交付到第二张子表。**

## 1. 数据流

```
CDE 受理列表（真浏览器，承办日期倒序，日期游标翻页 + 本地过滤）
   ▼
output/history/pipeline-cde.json      公司×资产 行（口径内 594 条）
   ▼  CT.gov 按代号/INN → 期次；CDT 按代号/中文名补中国试验
scoring.js  D1-D7 → 分数 + 档位（A≥20 / B≥16 / C≥12）
   ▼  窗口 18 个月 + 只 A/B
子表「临床阶段管线」  22 列（数据 18 + 销售手填 4）
```

## 2. 口径（代码在 `scope.js`，配置在 `config/pipeline-scope.json`）

| 项 | 决策 |
|---|---|
| 药品类型 | 只要**化药**（销售确认；与调研「中药浸膏」结论相反，以销售为准） |
| 注册分类 | **1 类创新药**。2.x 改良型（新复方/新剂型/新途径/新适应症）已剔除——多为老药改剂型，看起来就是仿制；2.2 新剂型理论上对包装有新需求，加回只改 `reg_class` |
| 申请类型 | **新药**。进口（`J` 前缀）剔除 317 行：`J` = 境外主体持证，**≠ license-in 交易** |
| 行粒度 | 一行 = 公司 × 资产（`PIPE\|公司\|资产`）；事件不另开行 |
| 剂型缺失 | 不出局，D1=0 降权；只有已确认的注射剂/生物制品出局（G1） |

## 4. 不做（写死，防蔓延）

- **HKEXnews**：ToS §5(iii) 明文禁止程序化访问（含禁建库、禁 data mining）。替代：cninfo 已收录港股公告
- **医药魔方 / 药智 / Insights**：禁止爬，仅人工导出交叉校验
- 融资/IPO 全量监控、CSP 推荐矩阵（剂型未知时给了就是假数据）

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 公司名歧义错并（两家共用一行 → 反馈互相覆盖） | 保守：只做机械等价 + 别名表精确匹配；不确定就留两行 |
| CT.gov 短代号撞车（`HP-001`、`MI078`） | 要求代号出现在本试验干预名/标题；A 档人工核 |
| CDE 列表倒序是隐式假设 | 两道自检：翻页日期不得变大 / 首页日期不得早于游标 |
| 评分卡在只有 D1-D3 时像"剂型筛选器" | 用真实分布校准阈值；宁可 A 档少，不可错 |

## 6. 决策日志

**2026-11-11**

| 决策 | 内容 | 理由 / 代价 |
|---|---|---|
| 排除进口 | `exclude_import: true`，剔除 `J` 前缀 317 行（1125→808） | 销售要"只要国产资产"。`J`=进口≠license-in；license-in/out 在 CDE 里不可见。代价：会剔掉"境外公司在中国申报的创新药"（可回滚） |
| 搁置 web app | 不换企微表格、不建数据库 | 生产表 337 行只有 7 条有跟进状态（渗透率 2%），此基线加"要登录的新系统"只会没人用。若将来做：SQLite 是单机文件库不能远程写，服务器侧应放 Postgres 或"SQLite + HTTP 入库接口" |
| 采集与服务分离 | 采集留本机 WSL（真浏览器过瑞数）；服务/库放公司服务器走 portproxy | 未实施。服务器五项待确认：OS/权限、Node 版本、端口、是否已有 DB、备份 |
| 数据只在一台机器跑采集 | 生产化后：生产机跑采集，开发机只改代码 | 否则两个 `pipeline-cde.json` 各跑各的，口径漂移 |
